TypeScript authorization SDK

permio is the official TypeScript/JavaScript client for the perms.io API. It wraps the API in a few calls for asking “may this principal do X on this resource?”. It also gives you typed errors, retries for idempotent reads and async iterators over list endpoints. The full generated API is there too, as an escape hatch.

  • Runs on Node 18+, edge runtimes and browsers. It talks gRPC-web over fetch.
  • Ships ESM and CommonJS builds with bundled type definitions.
  • Has three runtime dependencies: @bufbuild/protobuf, @connectrpc/connect and @connectrpc/connect-web.

Versions

Batch checks, groups and access queries are available from 0.2.0 (npm).

Create a client

Section titled “Create a client”

The constructor checks the API key’s format and checksum straight away. A mistyped or truncated key throws PermioConfigError before any request is sent. See API keys for the format.

Keep API keys on the server

The SDK works in browsers, but an API key in a browser bundle is visible to anyone who loads the page. Call perms.io from your backend, route handlers or middleware.

Options

Section titled “Options”
Option Type Default Description
apiKey string required A perms_… key from the dashboard, or a legacy JWT key.
baseUrl string https://api.perms.io API host.
project string none Default project name for check* and list* helpers. Each call can override it.
timeoutMs number 10000 Timeout for each attempt, in ms. 0 disables it.
retries number | RetryOptions 2 Retries for idempotent reads. A number sets maxRetries; see Retries and timeouts.
fetch typeof fetch globalThis.fetch Custom fetch, for example to add an agent, or for tests.
transport Transport gRPC-web Advanced: a Connect transport to use instead, for example createRouterTransport in tests. baseUrl and fetch are then ignored.

The production default is https://api.perms.io. Versions 0.2.1 and earlier default to https://temp-api.perms.io, which is being retired: upgrade, or set baseUrl.

The client also exposes permio.project, permio.baseUrl and permio.apiKeyKind ("opaque" or "jwt").

Checking permissions

Section titled “Checking permissions”

All the check helpers take the same parameters (CheckParams):

Parameter Description
principal Required. The ID of the user, service or other principal being checked.
resource / resources One resource URI, or several. Every resource is checked.
permission / permissions One permission name, or several.
project Project to check in. Defaults to the client’s project.
signal An AbortSignal that cancels the call.
timeoutMs Overall deadline for this call in ms, across retries.
headers Extra request headers.

You can pass both the singular and the plural form; they are merged. Duplicates are removed before sending. A single check accepts up to 100 resources and 100 permissions.

check

Section titled “check”

Resolves to true when the principal holds every permission on every resource:

A principal that lacks the permission is a normal answer: check resolves to false. It only throws when the call itself fails, for example because of a bad key, malformed input or network trouble.

checkDetailed

Section titled “checkDetailed”

Same question, but it also tells you what is missing, per resource and in request order:

missing is an array of { resource: string; permissions: string[] } (MissingPermission), and is empty when allowed is true.

Section titled “assert”

Resolves when the principal is allowed and throws PermioDeniedError when it is not. The error carries principal and missing:

Section titled “checkAny”

Resolves to true when, on every resource, the principal holds at least one of the permissions. It is still a single API call:

checkAll

Section titled “checkAll”

An alias of check: every permission on every resource.

Batch checks

Section titled “Batch checks”

Available from 0.2.0

check gives one answer for all its resources together. batchCheck answers each resource separately, which is what you need to filter a list or decide which rows get an “edit” button.

batchCheck

Section titled “batchCheck”

Resolves to a Map<string, boolean> from resource URI to allowed, with one entry per distinct resource, in request order:

batchCheckDetailed

Section titled “batchCheckDetailed”

Same question, but resolves to a BatchCheckEntry[] in request order:

BatchCheckParams:

Parameter Description
principal Required. The principal being checked.
resources Required. Resource URIs, each answered separately. Duplicates are sent once. More than 100 are split into several calls, sent in parallel.
permission / permissions One or several permission names, up to 100. A resource is allowed only with all of them.
project, signal, timeoutMs, headers As for check.

The SDK fails closed: if the API’s answer doesn’t have exactly one result for each requested resource, it throws a PermioError instead of guessing.

Groups

Section titled “Groups”

Available from 0.2.0

A group is a named set of principals in a project. Grant to the group’s principal ID, group:<slug>, and every member holds the grant. Checks include the principal’s groups automatically.

group(slug)

Section titled “group(slug)”

Returns the group’s principal ID. It throws PermioValidationError unless the slug is 1–64 lower-case letters, digits and hyphens.

permio.groups

Section titled “permio.groups”

Every method that takes a group accepts its slug ("editors") or its principal ID ("group:editors").

Method Resolves to
create(name, { description? }) Group. Throws a PermioError with code Code.AlreadyExists if the project already has a group with this name.
get(name) Group. Throws PermioNotFoundError if it doesn’t exist.
update(name, { description }) Group. Replaces the description; a group can’t be renamed. Throws PermioNotFoundError if it doesn’t exist.
delete(name) void. Deletes the group, its memberships and every grant made to it. Resolves whether or not it existed.
list({ search? }) Async iterator of Group, ordered by name.
addMembers(name, principals) AddMembersResult: { added: string[]; existing: string[] }, in request order.
removeMembers(name, principals) RemoveMembersResult: { removed: string[]; notMembers: string[] }, in request order.
listMembers(name) Async iterator of GroupMember (principalId, createdAt), ordered by principal ID.
listForPrincipal(principal) Async iterator of the Groups the principal is a member of, ordered by name.
  • addMembers and removeMembers take 1–100 principals; duplicates are removed. addMembers rejects group: IDs with PermioValidationError, because groups can’t contain groups.
  • Every method also takes project, signal, timeoutMs and headers. The list methods take pageSize too, and their timeoutMs and headers apply to each page.
  • Group has id, organisationId, projectName, name, description, principalId ("group:<name>"), createdAt and updatedAt.

Reading groups works with a check-access API key. Creating, updating and deleting groups and changing members needs a key with full access, and changing members also needs the right to grant across the project. See Permissions you need.

Access queries

Section titled “Access queries”

Available from 0.2.0

These answer “where?” and “who?” rather than “may they?”. The Filtering lists and building share dialogs guide shows them in context.

listAccess

Section titled “listAccess”

Answers “where may this principal use this permission, at or below under?”. It follows every page and resolves to an AccessScopes object:

ListAccessParams:

Parameter Description
principal Required. Access through roles and groups counts.
permission Required. One permission name.
under Required. Only resources at or below this URI are considered. A _ segment here is literal.
project, pageSize, signal, timeoutMs, headers As for the list helpers: timeoutMs and headers apply to each page.

AccessScopes:

Member Type Description
under string The URI that was asked about.
coversAll boolean The principal holds the permission on under itself, so on everything below it. scopes is then a single subtree scope for under.
scopes readonly AccessScopeInfo[] { uri, kind }, ordered by URI. kind is "subtree", "pattern", "exact" (reserved, not returned today) or "unknown" (a kind this SDK version doesn’t know; it never matches).
isEmpty boolean No access anywhere under under.
allows(uri) boolean Whether uri is covered. Matches per segment: /a/b covers /a/b/c but not /a/bc. Malformed URIs are never allowed.
toPrefixes() string[] The subtree URIs, for prefix filters. Prefixes covered by a shorter one are dropped. Pattern scopes aren’t included.
patterns() string[] The pattern URIs, with _ segments.
hasPatterns boolean Some scope is a pattern, so toPrefixes() alone doesn’t cover everything.
exact() string[] The exact URIs. Empty today.
toRegExp() RegExp One anchored regular expression matching exactly what allows() accepts. Usable in MongoDB $regex and, via .source, PostgreSQL ~. Matches nothing when there are no scopes.

Caution

A prefix p from toPrefixes() means p and everything below it. Filter with path = p OR path starts with p + "/", never a bare “starts with p”, which would let /documents/1 match /documents/12. In SQL, use starts_with(path, p || '/') rather than LIKE, where _ is a wildcard.

For a URI outside under, allows() returning false means “not asked”, not “denied”. The API key needs permission.check on under and principal.assignment.get on the principal.

whoHasAccess

Section titled “whoHasAccess”

Answers “who has access to this resource?”. It follows every page and resolves to an AccessEntry[], ordered by principal ID:

WhoHasAccessParams:

Parameter Description
resource Required. The resource to look at. A _ segment here is literal.
permission Optional. Only count grants that confer this permission, so a principal is listed exactly when check() passes for it through its own grants (or, for entries with viaGroup, through that group). Unset, any grant counts.
expandGroups Optional. Also list every member of each listed group, once per group, with viaGroup set.
project, pageSize, signal, timeoutMs, headers As for the list helpers: timeoutMs and headers apply to each page.

AccessEntry has principal, isGroup, viaGroup (a group slug, or undefined) and via, the grants that give the access, most specific first. Each grant (AccessGrantInfo) has:

  • resource: the URI the grant was made on (the resource, an ancestor, or a _ wildcard URI that matches it);
  • inherited: true unless the grant was made on exactly the resource;
  • match: "exact", "ancestor", "wildcard" or "unknown";
  • source: { type: "role", id, name }, { type: "direct" } for directly granted permissions, or { type: "unknown" }.

The API key needs principal.list and principal.assignment.list on the project.

Resource URIs

Section titled “Resource URIs”

Resource URIs are paths such as /projects/p1/documents/42. A grant on a URI also covers every URI beneath it. See Resources and inheritance for the full rules.

resource(...segments)

Section titled “resource(...segments)”

Builds a URI from raw segments. It adds the leading / and percent-encodes each segment, so an ID that contains /, spaces or other reserved characters stays a single segment:

On top of encodeURIComponent, it also encodes ! ' ( ) *, because the API rejects ( ) * in segments. Empty segments throw PermioValidationError.

Tip

Build URIs the same way when you grant and when you check, or they will not match.

Other helpers

Section titled “Other helpers”
Export Description
encodeSegment(segment) Encodes one segment the way resource() does.
assertResourceUri(uri) Throws PermioValidationError unless uri has the basic shape the API accepts: a leading /, no empty segments, no whitespace or control characters, and at most 2048 bytes.
MAX_RESOURCE_URI_LENGTH 2048.

Every check runs assertResourceUri on its URIs before sending. The API enforces the remaining rules, such as no ( ) [ ] { } * + ? | ^ $ \ in segments, and answers with InvalidArgument, which the SDK raises as PermioValidationError.

Errors

Section titled “Errors”

Every error the SDK throws extends PermioError. It has these properties:

  • code: the gRPC status Code. Code is re-exported from permio.
  • codeName: the code’s name in lower case, for example "permission_denied".
  • metadata: the response headers and trailers.
  • cause: the original error, usually a ConnectError.
Class When
PermioConfigError Bad client setup: a malformed API key, no project, an invalid baseUrl or no fetch.
PermioAuthError Unauthenticated: the key is missing, unknown or invalidated.
PermioPermissionError PermissionDenied: the API key lacks the rights for this call. missing lists what it lacks when the API says.
PermioValidationError InvalidArgument, or the SDK’s own input checks (for example a URI without a leading /).
PermioNotFoundError NotFound, for example getPermission for a name that does not exist.
PermioUnavailableError Unavailable, including network failures.
PermioTimeoutError DeadlineExceeded, including the SDK’s own timeouts.
PermioDeniedError Thrown only by assert(), when the principal is not allowed. Has principal and missing.

Any other status is a plain PermioError with the matching code.

Denied is not an error

PermioPermissionError is about the caller. It means your API key is not allowed to make the call: for Check, the key needs permission.check on the checked resources and on the principal. A principal failing a check is a normal result: check() returns false and assert() throws PermioDeniedError.

PermioPermissionError.missing uses the API’s fully qualified URIs (/organisation/{org}/project/{project}/...), not the URIs you sent.

toPermioError(error) converts any thrown value into the matching PermioError subclass. parseMissingPermissions(message) extracts the missing list from a PermissionDenied message. You only need these if you build your own transport or client.

Retries and timeouts

Section titled “Retries and timeouts”
  • Retries: idempotent reads (Check, BatchCheck, and every Get* and List* RPC, including ListAccess, ListPrincipalsWithAccess and the group reads) are retried on Unavailable and DeadlineExceeded. They are retried twice by default, with exponential backoff and jitter. Network failures count as Unavailable.
  • Writes (every Create, Update, Delete, Grant, Revoke, Invite, adding and removing group members, and so on) are never retried.
  • Timeouts:
    • The client’s timeoutMs applies to each attempt (default 10 s).
    • A call’s timeoutMs is an overall deadline across all attempts.
    • Aborting signal cancels the call and any pending retry.

RetryOptions has these fields:

  • maxRetries: retries after the first attempt. Default 2.
  • baseDelayMs: the first delay, which doubles each time. Default 100.
  • maxDelayMs: the cap on a single delay. Default 2000.

isIdempotentMethod("permio.permissions.v1.PermissionsService.Check") tells you whether the SDK retries a given RPC.

Listing with iterators

Section titled “Listing with iterators”

List RPCs are paginated with a cursor (see Pagination). The helpers return async iterators that fetch pages as you go:

Method Yields
listPermissions(params?) Permission
listRoles(params?) Role (with its permissions)
listPrincipals(params?) string principal IDs that have grants in the project
listAssignments({ principal, ... }) Assignment (resourceUri, permissions, roles)
groups.list(params?) Group (from 0.2.0; see Groups)
groups.listMembers(name, params?) GroupMember (from 0.2.0)
groups.listForPrincipal(principal, params?) Group (from 0.2.0)

Each method takes these parameters:

  • project
  • pageSize: 1–100, default 100
  • signal: stops iteration and any in-flight request
  • timeoutMs: per page
  • headers

listPermissions, listRoles and listPrincipals also take search, which filters by name.

Raw clients (full API)

Section titled “Raw clients (full API)”

permio.permissions and permio.organisations are the generated Connect clients for permio.permissions.v1.PermissionsService and permio.organisation.v1.OrganisationService. Authentication, timeouts, retries and error mapping are already applied. Every RPC in the API reference is available, with request and response types generated from the protobuf definitions. What a key can call

By default an API key has check access: it can run checks and access queries, and read permissions, roles, principals, assignments and groups. Creating, updating or deleting permissions, roles and groups, granting or revoking, and changing group members needs a key with full access. See API keys.

How it talks to the API

Section titled “How it talks to the API”

The SDK uses the gRPC-web protocol over fetch (through @connectrpc/connect-web). The perms.io gateway accepts it directly from servers, edge runtimes and browsers. The key is sent as Authorization: Bearer <key>. Timeouts are enforced on the client, so no grpc-timeout header is sent.
